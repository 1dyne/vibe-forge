## 단계와 승인

brainstorm → circuit → mockup → handoff → workshop.

1. 아이디어와 PNG/JPEG/WebP 이미지 최대 3장을 입력한다. 서버가 제목을 요약하고 프로젝트를 만든다. 이미지는 실제 Claude vision 입력으로 전달한다.
2. 브레인스토밍에서 불완전한 요구는 대장이 추가 질문한다. 핵심 동작, 도구 체크리스트(없음 가능), 펌웨어 경험을 확인한다. 경험은 설명에만 반영한다.
3. 사용자가 계획 시작을 선택하면 회로를 먼저 생성한다. 회로 방향 승인 시에만 3D 산출물이 생성된다.
4. 3D는 실제 치수로 만든 3차원 좌표를 투영한다. 드래그/방향키 회전, 확대, 초기화가 가능하다. 실제 부품 형상을 검증한 CAD라는 뜻은 아니다.
5. 3D 승인 후 사용자/AI 작업 표와 구매 상태를 확인한다. 선택한 HW/SW/ME/ID 역할과 대장간에 입장한다.
6. 설계 다시 논의는 기존 자료를 보존하고 회로/3D 승인을 해제한다. 재생성 후 다시 승인한다.

승인은 사용자의 설계 방향 승인이다. 전압 실측·컴파일·실물 적합성의 검증 합격과 분리한다.

## 역할과 작업실

- 대장: 목적, 일정, 역할의 의존성과 지시 조율.
- HW: 회로·펌웨어. 평가 모드는 도구 확인과 구체적 계측 요청·트러블슈팅.
- SW: 웹·앱 코드. 평가 모드는 완성된 결과 검사만 하며 파일 생성 금지.
- ME: 구조·부품 배치. 평가 모드는 조립 후 치수 실측 요청과 조정 검토.
- ID: 형태·사용 경험. 평가 모드는 착용감·안전성 충돌 검토.

작업 모드는 Sonnet, 평가 모드는 Opus를 사용한다. 메인방은 선택한 팀의 역할별 답변을 구조화된 한 번의 모델 요청으로 조율한다. 개별방은 해당 역할만 응답한다. 장시간 독립 백그라운드 워커를 실행하는 구조는 아니다.

각 방의 대화는 동일 프로젝트 저장소에 기록한다. 변경 제안·관측·해결 여부의 요약, 제출된 계측 결과, 구매 상태와 작업 초안은 다음 모든 역할의 모델 입력에 포함된다. 승인된 설계는 채팅으로 자동 덮어쓰지 않는다.

작업 요청 시 코드/문서 초안을 별도 파일로 저장·다운로드할 수 있다. 해당 파일은 자동 실행·컴파일·배포하지 않는다. 평가 모드의 파일 생성은 서버에서 거부한다.

## 저장·검증 경계

- 로컬 JSON의 원자적 교체 및 직렬화된 갱신. 느린 AI 호출 후 저장 시 revision 충돌을 검사.
- 공통 도구·경험 프로필은 다음 프로젝트에 재사용. 프로젝트의 핵심 동작은 각각 다시 확인.
- 구매 예정/주문/수령/문제를 공통 대화에 기록. 가격·재고 검색은 아직 미연결이므로 구매 전에 확인하도록 안내.
- 결과 제출은 HumanTask의 보고 완료이고 Evaluator의 pass와 구분.
- 3D 승인 전 파일 다운로드도 서버에서 차단.
- 실물 CAD 렌더/STL, 직접 장치 업로드, 클라우드 DB/워커, 독립 백그라운드 에이전트 실행은 후속 범위.
