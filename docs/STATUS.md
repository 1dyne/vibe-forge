## 이번 구현

- 좌측 프로젝트·작업실 / 중앙 연속 채팅 / 우측 BOM·할 일·회로·회전 가능한 3D 탭.
- 제공한 idle, thinking_1, thinking_2 캐릭터와 지정한 회색·민트·검정 브랜드 색상.
- 아이디어 자동 제목, 추가 질문, 이미지 첨부, 도구 체크리스트, 펌웨어 경험 프로필.
- 아이디어 → 회로 → 회로 승인 → 3D → 3D 승인 → 작업 분담 → 대장간의 서버 승인 경계.
- 대장 및 HW/SW/ME/ID 작업실, 참여 토글, 역할별 작업/Evaluator 모드.
- 모든 방의 변경 제안·관측·해결 사항, 구매 상태, 제출 결과, 작업 파일을 공통 문맥으로 공유.
- 작업 모드의 코드/문서 파일 저장·다운로드. 평가 모드는 파일 변경 금지.
- 구매 예정·주문·수령·문제 기록과 HumanTask 결과 제출. 제출만으로 unknown을 pass로 바꾸지 않음.
- 회로의 단자/net 시각화, OpenSCAD·Arduino 파일, HW/SW 초기 평가, 승인 후 3D 회전·확대.
- 레벨시프터 양쪽 net 분리, 불필요 부품 생략, 디지털 버튼 입력 펌웨어 수정.
- 원자적 로컬 저장과 revision 충돌 방지, 다음 프로젝트에 도구·경험 재사용.
- 비용 장부에서 실제 사용량 전체 반영. 작업실 호출 전 토큰 수를 확인하여 완결된 응답 예산이 부족하면 유료 생성을 시작하지 않음.

- 자동 검사 23개 통과, TypeScript 검사와 프로덕션 빌드 통과.
- 실제 Sonnet으로 검증용 버튼 LED 프로젝트 생성·회로 계획. Opus HW/SW 초기 평가 실행.

- HW 개인방의 실제 Opus 평가에서 멀티미터 구매 거절에 대한 대체 관찰 안내와 ME 변경 제안 공유 확인.
- ME 파일 생성 live 재검증 성공: 메인방의 8mm 변경 제안을 읽고 `button_test.scad`를 작성·저장·다운로드했으며 기존 승인 설계는 유지함. 실제 Sonnet 메인 팀 응답과 Opus HW 개별 평가도 시연 프로젝트에서 확인.
- 이미지 MIME 검증과 모델 vision 입력 변환 검사 통과. 실제 이미지 해석 품질은 추가 live 검증 필요.
- 브라우저 검증용 프로젝트는 이름에 ‘검증용’을 표시하고 실제 사용자 프로젝트와 분리.

## 현재 경계와 후속 작업

- 로컬 JSON 개발 저장소를 사용한다. Postgres migration·worker 골격은 있으나 운영 DB/queue 연결과 독립 백그라운드 에이전트는 미완성.
- 메인방은 한 번의 모델 요청으로 선택한 역할의 답변을 조율한다. 개별방은 해당 역할만 응답한다.
- 3D는 제안 치수 기반의 회전 가능한 기구 목업이다. 실제 부품 형상·공차 검증, OpenSCAD 렌더/STL, 실물 조립 검증은 별도다.
- 파일은 자동 실행·컴파일·배포하지 않는다. Arduino IDE에서 사용자가 실행하고 결과를 제출하는 MVP 흐름이다.
- 실시간 판매처·가격·재고 검색은 아직 미연결이며 BOM에서 구매 전 확인을 안내한다.
- 회로 배선 과정 재생 기능은 확장 범위로 남아 있다.
- 기존 승인된 설계는 개인방에서 만든 초안으로 자동 덮어쓰지 않는다. 설계 다시 논의 후 재승인한다.

API 키는 출력하지 않았다. APP_MODE=live이며 2026-09-17 사용자의 명시적 승인으로 앱의 턴당·일일 비용 한도를 `Infinity`로 해제했다. 사용량 장부 기록은 계속하며, 제공자 계정 한도는 별개다. 유한한 금액으로 다시 설정하면 앱의 비용 제한이 복구된다.
