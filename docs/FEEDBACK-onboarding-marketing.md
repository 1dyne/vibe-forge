# 달그락 대장간 온보딩·마케팅 피드백

작성: 2026-11-13. `/find` 온보딩 코드(`apps/web/app/find`, `apps/web/lib/find`), `docs/FIND*.md`, `docs/WORKFLOW-v0.6.md`, `docs/STATUS.md`, 가입·연결 화면 문구를 기준으로 봤다.

질문: 하드웨어를 전혀 모르는 비개발자도 달그락 대장간으로 하드웨어 프로젝트를 쉽게 할 수 있다는 것이 잘 전달되려면, 마케팅과 온보딩을 어떻게 바꾸면 좋을까?

## 핵심 진단: 온보딩은 아이디어 찾기 게임이고, 하드웨어를 몰라도 된다는 메시지는 화면에 없다

`/find`는 "아이디어 찾기 → 공유 → 줄 서기 → 마을 구경"이 아주 잘 다듬어져 있다. 그런데 이 흐름 어디에도 아래 내용이 나오지 않는다.

- "회로·코딩 몰라도 돼"라는 말이 없다. `app/find`, `lib/find` 전체에서 "몰라", "납땜", "비전공" 같은 단어가 0건이다.
- 창업자 이야기가 없다. "정치학 전공, 39일, 12만 원, Onyx SDI"는 README에만 있다.
- 실제 대장간 결과물(회로, 부품 목록, 사람이 할 일 카드)을 보여주지 않는다.

그래서 사용자가 마지막에 받는 인상은 "재밌는 도깨비 게임이었고, 진짜 만드는 건 나중에 열린대"다. 대기 화면의 손가락 5단계도 아이디어 1개만 켜져 있고 부품·회로·하우징·조립은 전부 "오픈하면 켜져"로 잠겨 있다(`waitlist.tsx`). 비개발자가 제일 의심하는 "내가 정말 회로를 할 수 있나?" 부분이 하필 다 잠겨 있다.

## 1. 마케팅: 주장보다 증거로 세 가지 두려움을 하나씩 풀기

| 두려움 | 지금 메시지 | 바꿀 증거 |
|---|---|---|
| 용어를 몰라 | 없음 | 부품을 이름이 아니라 하는 일로: "무게를 재는 판 → 컵을 들었는지 알아채". `lib/find/parts.ts`에 이미 이 구조가 있다 |
| 돈 날릴까 봐 | "부품값만 해도 서러우니까"(유머로만 처리) | "사기 전에 다른 AI가 한 번 더 검토해요"와 예상 비용 범위("3~5만 원") |
| 망가뜨리거나 다칠까 봐 | 거절할 때만 "저전압만 다뤄" | 처음부터 "USB 5V만 다뤄요. 납땜 없이 꽂는 방식부터 시작해요" |

- **대표 카피는 창업자 이야기로.** "아두이노가 뭔지도 몰랐던 정치학 전공자가 39일·12만 원에 직접 쓸 재활 인솔을 만들었어요. 그 방법을 그대로 옮긴 게 달그락이에요." `/find` 첫 화면 아래와 OG 설명(`lib/find/site.ts`의 `FIND_DESCRIPTION`)에 넣는다.
- **"이걸 받게 돼요" 실물 미리보기.** 시연 영상(`artifacts/demo`)에서 사람 손이 선을 꽂는 장면, 부품 목록, "멀티미터로 여기를 재주세요" 카드를 15초 쇼츠로 잘라 쓴다. "비전공자 ○○ 씨의 첫 물건" 시리즈.
- **메이커 커뮤니티가 아니라 문제가 있는 사람들에게.** 꼬물마을은 반려인·돌봄, 째깍마을은 공부·업무, 교실 신호등은 교사. "고양이 밥 먹었는지 알려주는 그릇, 코딩 몰라도 주말에 만들었어요"처럼 문제를 앞세운다.
- **부품 묶음 판매가 가장 큰 전환 레버.** 누코드 쿠폰 연동이 이미 있으니 "네 도깨비불 부품, 한 박스로 받기"까지 가면 부품 구매라는 장벽이 통째로 사라진다.
- **"추가 비용 없이"는 조심.** 실제로는 Claude 구독과 커스텀 커넥터가 필요하다. 커스텀 커넥터를 쓸 수 있는 요금제를 확인한 뒤 "Claude 유료 구독이 있으면 추가 비용 없이"처럼 조건을 밝힌다.

## 2. 온보딩 변경안 (우선순위 순)

### ① 결과 화면에서 설계도 첫 장을 지금 보여주기 (효과가 제일 큼)
지금은 결과 화면(`find-flow.tsx`)에서 "대장간이 열리면 회로도 첫 장을 보내줄게"라고 약속만 한다. 바로 보여준다.
- `parts.ts`로 필요한 것 3~4개를 쉬운 말로: "알아채는 것: 무게 판 / 알려주는 것: 작은 불빛 / 머리: 작은 보드"
- 난이도 배지: 납땜 없음 가능 · 예상 2~3시간 · 3~5만 원
- 손가락 5단계에서 부품 단계를 반쯤 켜고, 회로·3D만 잠근다.
- 닮은 메이커 프로젝트는 "고수들이나 하는 거구나"로 읽힐 수 있다. "이미 누군가 만든 적 있어 = 너도 가능해"로 바꾸고 미리보기 아래로 내린다.

### ② 도깨비불과 대기 신청 사이에 30초 대장간 맛보기
사용자가 받아 적은 문장을 넣은 고정 연출(모델 호출 없음):
1. 대장이 하나만 묻는다: "집에 있는 공구 있어?"
2. HW 달그락이 회로 썸네일을 보여준다.
3. 사람이 할 일 카드: "빨간 선을 5V에 꽂아요"(사진 포함)
4. 평가 모드: "사기 전에 확인했어요. 이 부품은 이 보드와 맞아요."

### ③ 첫 화면에서 경험 질문 하나 받기
- "뭘 만들어 본 적 있어? 처음이야 / 조립 키트는 해봤어 / 납땜도 해봤어"
- "처음이야" → "그럼 납땜 없이 꽂는 길로 안내할게"
- 오프닝 대사(`opening.tsx`)에 "회로도 코딩도 몰라도"를 넣는다. 지금은 "상상만 하던 것도 뚝딱"에서 끝난다.

### ④ 세계관 어휘 줄이기
- 첫 세션엔 도깨비불(=아이디어), 장작(=조건)만 남기고 처음 나올 때 쉬운 말 부제를 붙인다.
- 마을·기와·등불은 리텐션 장치다. 첫 방문→가입 경로에는 노출하지 않는다.
- "불이 꺼지려 해!" 압박은 시험처럼 느껴질 수 있다. 바닥값을 올리거나 화면에서만 줄어들게 하는 쪽도 고려.

### ⑤ 진짜 절벽은 커넥터 연결
초대 코드 → 가입 → 복구 코드 → 메일 인증 → claude.ai 커스텀 커넥터 추가 → 프로젝트 지침 붙여넣기 → + 메뉴에서 커넥터 켜기. 연결 화면엔 "MCP", "Claude Code나 Codex", "SPEC.md·AGENTS.md" 같은 개발자 말이 그대로 나온다.
- **도깨비불 이어 붙이기:** 오픈 메일 링크를 누르면 도깨비불 문장으로 프로젝트가 이미 만들어져 있고 첫 회로 초안까지 생성돼 있게 한다(HANDOFF §7의 의도). 첫 경험이 설정 화면이 아니라 "내 회로도"여야 한다.
- **연결 안내:** 제목을 "Claude에 달그락 연결하기 (3분)"으로, 단계마다 스크린샷·GIF, "막히면 지금 화면을 캡처해서 보내줘" 버튼. 개발자 용어는 접어서 숨긴다.
- **대기 신청에서 미리 묻기:** "Claude 쓰고 있어?" — 구독이 없는 사람에게 오픈 전에 따로 안내.

## 3. 지표도 하드웨어 기준으로

지금 핵심 지표(공유율, 가입률, 추천 계수)는 전부 바이럴 지표다. 추가할 것:
- 경험 질문에서 "처음이야" 비율과 그중 대기 신청 비율
- 오픈 뒤 첫 회로 승인률, 첫 부품 주문률
- 목표 지표: 비전공자가 첫 물건을 완성한 수 → 이 숫자가 다시 마케팅 증거가 된다

**하나만 고른다면 ①번.** `parts.ts`가 이미 있어 결과 화면에 설계도 첫 장 미리보기를 붙이는 게 가장 싸고 효과가 크다.
