# 내 도깨비불 찾기 — 구현 핸드오프

달그락 대장간의 온보딩 겸 바이럴 페이지. 유저가 만들고 싶은 것(또는 요즘 귀찮은 것)을 넣으면, 키워드를 "장작"처럼 넣어 아이디어를 구체화하고, 그 결과를 **내 도깨비불**(공유 카드)로 받는다. 마지막 장에서 "이제 몸을 만들어줄 차례야"로 달그락 대장간 오픈 알림 신청을 받는다.

> 아이디어 = 불, 만든 물건 = 그 불이 얻는 몸. 캐릭터는 손 모양 도깨비불이고 입 안에 불이 산다.

## 0. Claude Code에 처음 줄 말 (예시)

```
이 폴더의 HANDOFF.md와 prototype.html을 읽어줘.
prototype.html은 화면 흐름·문구·애니메이션·불 규칙의 기준이야(동작하는 목업).
HANDOFF.md §4~§7의 실제 기능(AI 1회 호출, 프로젝트 매칭, 공유 카드, 대기열)을 붙여서 구현해줘.
스택은 [달그락 레포 스택 / 독립 정적 페이지 + 서버 함수 1개] 로 가자.
먼저 구현 계획과 질문을 정리해서 보여주고, 내가 확인하면 시작해.
```

## 1. 파일

| 파일 | 내용 |
|---|---|
| `prototype.html` | 단일 파일 목업. 브라우저로 바로 열림. 화면·문구·모션·불 규칙의 **기준(source of truth)** |
| `assets/dokkaebi-sprite.png` | 다인이 그린 캐릭터 스프라이트 시트 (원본 그대로) |
| `assets/dokkaebi-sprite.json` | 위 시트의 프레임 정보 (SpriteFrame 형식) |
| `HANDOFF.md` | 이 문서 |

목업에서 가짜인 것: 캐릭터(점선 자리만 있음, §9), 하드/소프트 판별(정규식), 키워드 목록(하드코딩), 닮은 프로젝트·일치율(예시 데이터), 순번·쿠폰·링크(`[대괄호]` 빈칸).

## 2. 화면 흐름 (모바일 우선, 최대 폭 430px, 흰 배경)

1. **시작** — 캐릭터 + 말풍선 "배고파… 만들고 싶은 거, 아니면 요즘 귀찮은 거 하나만 줘봐." / 입력창 / 예시 버튼 3개 / "아무거나 던져줘"(불편 예시 랜덤) / CTA "나와라, 뚝딱!"
2. **판별 중** — 캐릭터 갸웃 모션 + "음… 손이 가는 일인가?" (AI 호출 대기 시간을 이 연출로 가린다)
   - 소프트웨어 판정 → "이건 손 안 대도 되는 거야." + 바이브코딩 가이드 링크 + "근데 손을 대면?" 카드 → "하드웨어로 바꿔보기"
3. **장작 넣기** — 캐릭터(화력에 따라 커지고 손가락이 더 세게 흔들림) / 화력 게이지 / **받아 적기 칸**(문장이 실시간으로 써짐) / 키워드 버튼 / "이 불로 할래!"
4. **도깨비불 공개** — 이름("깜빡이는 책상 도깨비불"), 최고 화력, 형태·반응·감지 요약, 설계 한 줄, 닮은 프로젝트 가로 스크롤(이미지 + 일치율 + 닮은 점), "네 아이디어에만 있는 것", 카드 저장·공유, CTA "내 도깨비 만들러 가기"
5. **내 도깨비 만들기** — "불은 찾았어. 이제 몸을 만들어줄 차례야." / 손가락 5단계(아이디어 ✓ · 부품 · 회로 · 하우징 · 조립, 첫 번째만 불 켜짐) / 달그락 소개 / 이메일 → 대기 순번 + 메밀묵 초대(추천) 

달그락 소개 문구(확정):
> 말하면, 회로도부터 조립까지. 하드웨어 올인원 대장간.
> <small>이미 구독 중인 AI에 커넥터로 연결해서 추가 비용 없이 써요. 부품 불량으로 바꾸는 부품값만 해도 서러우니까.</small>

## 3. 불 규칙 · 받아 적기

`prototype.html`의 `FIRE` 상수가 기준. 튜닝은 여기서만.

- 시작 20, 바닥 8, 최대 100. 0.1초마다 −0.18 (가득 찬 불이 꺼지는 데 약 50초). 타이머는 없다 — **사그라드는 불**이 시간 압박 역할.
- 키워드 하나 +6, 처음 채우는 갈래 +10, 후속 키워드 +5 → 골고루·깊게 고를수록 센 불.
- 갈래 4개: 형태 / 반응 / 감지 / 누구. **반응 갈래가 불 색을 정한다**: 빛=보라 `#9B7BFF`, 소리=주황 `#FF8F3F`, 움직임=초록 `#3FBF6E`, 없음=청록 `#4FB3A6`.
- 단계 이름: <30 불씨, <55 모닥불, <80 활활, 그 이상 도깨비불 만개.
- **받아 적기**: `compose()`가 고른 키워드를 *형태 → 감지 → 반응 → 누구* 순서의 문장으로 다시 짠다. 화면은 이전 문장과 달라진 지점까지 빠르게 지우고(2글자/틱) 한 글자씩 다시 쓴다(38ms/글자). 고르는 순서가 엉망이어도 문장은 자연스럽게 유지된다.
  - 반응 후속 키워드(`pre:true`)는 동사 앞 꾸밈말, `tail:true`는 문장 끝 한 마디, `replaces`는 상위 키워드를 대체.
- 이 최종 문장은 **달그락 프로젝트를 만들 때 첫 명세 프롬프트로 그대로 넘길 수 있게** 저장한다(§7).

## 4. AI 호출 — 세션당 1회

키워드를 누를 때마다 부르면 느리고 운영비가 든다. **첫 입력 때 한 번만** 불러서 판별·안전·키워드 트리를 한꺼번에 받는다.

요청: `{ idea: string }` → 응답(JSON, 구조화 출력으로 강제):

```json
{
  "kind": "hardware | software",
  "reason": "한 줄",
  "safety": { "ok": true, "note": "" },
  "chips": {
    "root":   [{ "id": "f_desk", "cat": "형태|반응|감지|누구", "label": "책상 위에 두는", "say": "책상 위에 두는" }],
    "follow": { "f_desk": [{ "id": "f_tiny", "cat": "형태", "label": "손바닥만 하게", "say": "손바닥만 한", "pre": false, "tail": false, "replaces": null }] }
  }
}
```

- root 8~10개(갈래마다 2개 이상), follow는 root당 1~2개, 2단계까지.
- `say`는 §3의 문장 조립 규칙에 맞는 조각으로 생성하도록 프롬프트에 예시(목업의 ROOT/FOLLOW)를 넣는다.
- **안전 범위**: 저전압(대략 USB 5V·배터리 소형) 센서·LED·소형 모터만 다룬다. 상용전원(220V)·가열·고전류·의료 판단이 필요한 아이디어는 `safety.ok=false` + 정중한 안내("여긴 아직 저전압만 다뤄") 화면으로.
- 실패/타임아웃(3초) 시 목업의 고정 키워드 세트로 폴백. 같은 idea는 캐시.
- 가벼운 모델로 충분. 남용 방지로 IP당 레이트 리밋.

## 5. 닮은 메이커 프로젝트 — 이미지로 보여주기

직접 큐레이션한 프로젝트 DB(초기 30~50개)와 매칭. 실시간 웹 검색으로 일치율을 만들지 않는다(숫자가 그럴듯하게 지어지면 메이커들이 바로 알아챈다).

프로젝트 레코드:

```json
{
  "id": "led-water-coaster",
  "title": "물 마시기 알림 LED 코스터",
  "source_url": "https://...",
  "author": "...", "license": "CC BY-SA 4.0",
  "images": [{ "url": "...", "kind": "circuit | photo", "credit": "..." }],
  "tags": { "형태": ["책상 위"], "반응": ["빛", "깜빡임"], "감지": ["시간", "무게"], "누구": ["나"] },
  "parts": ["ESP32", "로드셀 HX711", "WS2812 LED"]
}
```

- **일치율** = 갈래별 태그 겹침의 가중합(예: 감지 0.35, 반응 0.3, 형태 0.25, 누구 0.1) × 100. 공식을 코드에 명시하고 AI가 숫자를 만들게 하지 않는다. 키워드 id ↔ 태그 매핑 테이블 필요.
- "닮은 점"은 겹친 태그로, "네 아이디어에만 있는 것"은 유저가 골랐는데 상위 프로젝트에 없는 태그로 만든다 → 그 부분이 "추가 설계 제안".
- 카드: 16:10 이미지(회로도 또는 작품 사진) + 제목 + 닮은 점 + 일치율, 가로 스크롤. 이미지 아래 출처·라이선스 표기 필수. 라이선스가 재게시를 허용하지 않으면 이미지 대신 링크만.

## 6. 공유 카드

- 9:16(1080×1920) PNG. 클라이언트 `html-to-image` 또는 서버 OG 이미지 생성(`satori` 등) 중 택1.
- 내용: "내 도깨비불", 불 색이 입혀진 캐릭터, 이름, 화력, 키워드 칩 최대 4개, 하단 "달그락 대장간 · 너의 도깨비불은? [링크]".
- Web Share API(파일 공유) → 미지원 시 다운로드.
- 결과 링크 `/f/:id`는 같은 카드를 OG 이미지로 갖는다(카톡·인스타 미리보기). 링크를 연 사람에게는 "나도 찾기" CTA.

## 7. 대기열 · 추천 (메밀묵)

```
waitlist(id, email, idea, sentence, picked[], peak_fire, fire_color,
         referral_code, referred_by, position, created_at, consented_at)
```

- 가입 즉시 순번 표시. 친구가 내 링크로 도깨비불을 찾고 가입하면 "메밀묵 한 그릇" → 순번 N칸 당김(값은 설정으로).
- 누코드 스토어 쿠폰: 지급 조건·방식은 다인이 누코드와 확정 후 채움(`[쿠폰 내용]`). 초기엔 수동 발급 가능하게 관리자 목록만.
- 이메일: 개인정보 수집·이용 동의 체크박스와 문구 필수. 오픈 시 "네 도깨비불의 설계도 첫 장" 메일 발송 — `sentence`를 달그락 프로젝트 생성 시 첫 프롬프트로 넣는다.
- 달그락에 합쳐질 때: 대기열 레코드 → 달그락 계정·프로젝트로 이관할 수 있게 `sentence`, `picked`를 보존.

## 9. 캐릭터 · 모션

캐릭터는 **다인이 그린 스프라이트를 그대로 쓴다.** 새로 그리거나 벡터로 따라 그리지 않는다. 목업의 `.dk-slot`(점선 상자)이 들어갈 자리다.

시트 사양 (`assets/dokkaebi-sprite.json`):
- 2560×2560 PNG, 투명 배경, 512×512 프레임 **25장**(5열×5행), 프레임당 80ms, 한 바퀴 2초, 정방향 반복.
- 그리드가 5×5라서 CSS `steps()` 한 줄로는 안 된다 → JS로 프레임 인덱스를 돌려 `background-position`을 바꾸거나 `<canvas>`에 그린다. (또는 빌드 때 가로 한 줄 스트립으로 변환 후 CSS `steps(25)`)
- 원본이 2.9MB라 모바일엔 무겁다 → 빌드 때 프레임 256px(표시 크기 최대 ~200px의 2배)로 줄이고 WebP로 변환. 원본은 보관.

화력 표현 (그림은 건드리지 않고 재생 방식으로):
- **재생 속도**: 화력이 셀수록 빠르게 (예: 프레임 간격 120ms → 50ms). `--fire-level`(0~100) 값이 목업에 이미 넘어가 있음.
- **크기**: 목업 `applyFire()`의 폭 공식 그대로 (130 + 화력×0.9 px).
- **기운**: 캐릭터 뒤 흐린 원(`.aura`)이 불 색(`--fire`)으로 커짐 — 목업에 구현됨.
- 장작 넣을 때 꿀꺽(gulp) 찌그러짐 + 불티 4개, 판별 중 갸웃(tilt), 둥실(bob)은 **컨테이너에 거는 모션**이라 목업 그대로 쓰면 된다.
- 반응 갈래에 따른 불 색은 지금 기운·게이지·버튼에만 적용. 캐릭터 그림 자체의 색을 바꿀지는 다인이 결정 (바꾼다면 색별 시트를 따로 받거나 CSS `hue-rotate`).
- `prefers-reduced-motion`이면 첫 프레임 정지.
